# 3.5 — Slack & Workflow Integration

A Slack app and an iPaaS-friendly automation surface so teams can interact with briefs where they already work. The Slack bot supports slash commands (view a brief, summarise gaps, ask questions about a brief), event subscriptions, and Block Kit-formatted notifications when a brief is completed or gap analysis finishes. For non-Slack workflows, Briefly exposes signed outbound webhooks plus a documented public API so users can wire Briefly into n8n, Workato, Make, or Zapier without writing code — with an option to ship a custom n8n node and Workato connector for a polished experience. Webhook delivery is durable: signed payloads, exponential retry through a background queue (Inngest / Vercel Queues), and a per-workspace delivery log. Depends on [[Features/3.3 - Public API]] for the inbound action surface.

## Remaining

- [ ] Slack App scaffolding — manifest, OAuth install flow, bot/user token storage per workspace
- [ ] Slash commands — `/briefly view <id>`, `/briefly gaps <id>`, `/briefly ask <id> <question>`
- [ ] Event subscriptions — message shortcuts and link unfurling for brief share URLs
- [ ] Block Kit renderer — brief summary card, gap analysis card, completion notification
- [ ] Outbound webhook registry — `webhook_endpoints` table, secret per endpoint, event filter (`brief.completed`, `gap_analysis.completed`, `brief.shared`, etc.)
- [ ] Signed delivery — HMAC SHA-256 signature header, timestamp, replay protection
- [ ] Retry queue — durable job per delivery attempt, exponential backoff, max attempts, dead-letter
- [ ] Delivery log UI — per-endpoint history, payload inspector, manual replay
- [ ] Public-API "actions" surface — RPC-style endpoints suitable for iPaaS triggers (create brief, fetch brief, list events)
- [ ] n8n community node + Workato connector (stretch) — wraps the public API + webhook subscription
- [ ] Docs — webhook event catalogue, signature verification example, iPaaS quick-start guides
